## Pourquoi le périmètre a changé le 2026-08-01

La version du 2026-07-31 portait trois écarts de contrat mineurs. **STORY-147 a été livrée le soir
même** et a modifié le contrat canonique de la balance — le keystone. Ce n'est plus de l'hygiène de

**Pourquoi une seule story et non deux :** la régénération des types **casse la compilation** de
15 fichiers d'un coup (le renommage `debit`→`mouvementDebit` est délibérément cassant côté backend,
D-147-1). On ne peut pas régénérer dans une story et réparer les appelants dans une autre sans
laisser le dépôt non compilable entre les deux. Les trois écarts d'origine sont donc **absorbés ici**
— ils sortent de la même régénération.

## Ce que STORY-147 a changé (vérifié dans le code livré)

### ① `LigneBalance` passe de 2 à 4 colonnes — renommage **cassant**

```ts
// AVANT                          // APRÈS
debit:  number;                   mouvementDebit:  number;
credit: number;                   mouvementCredit: number;
                                  soldeDebiteur:   number;   // XOR soldeCrediteur
                                  soldeCrediteur:  number;
```

**Invariant serveur** : `soldeDebiteur` et `soldeCrediteur` ne peuvent pas être tous deux non nuls
(400, « Compte « 411 » à double solde… »).

### ② `SommaireBalance` devient imbriqué, avec **deux** équilibres (D-147-3)

```ts
sommaire: {
  mouvements: { totalDebit, totalCredit, ecart, estEquilibre },
  soldes:     { totalDebit, totalCredit, ecart, estEquilibre },
  estEquilibre: boolean,   // conjonction des deux
}
```

Les anciens `totalDebiteur`/`totalCrediteur` **disparaissent** : ils sommaient des *mouvements* sous
un mot (*débiteur*) qui désigne un **solde**.

### ③ Checksum versionné `v2` (D-147-4) — **le test de parité de FE-026 va casser**

`v2` scelle les 4 colonnes ; `v1` reste en **vérification seule**. Le champ `checksumVersion` est
exposé ; son **absence** vaut `v1`.

⚠️ **Le vecteur v1 verrouillé côté front (`1864781c…`, dans `balance-checksum.test.ts`) porte une
AUTRE fixture que celle du backend.** C'est le **couple** (vecteur + jeu de données) qu'il faut
reprendre, pas le vecteur seul. Couple publié par STORY-147 :

```
v2 : 6c4a50087ced5290576aaa0b56629cf41ac51c94697092dc49650b9eae049569
v1 : 48f74471c3ba7b587dd100a40f45321e8e35ebe28e2f6f2c183d25b887d1f22a   (même fixture)

Fixture : exercice 2025-01-01T00:00:00.000Z → 2025-12-31T00:00:00.000Z, sage/SN/version 1,
          deux lignes — 601 « Achats » mvt 1000/0 solde 1000/0
                      · 701 « Ventes » mvt 0/1000 solde 0/1000
          toutes niveauPreuve: fichier
```

### ④ `POST /balances` exige les **4** champs — aucun optionnel, aucun dérivé (D-147-8)

« Un client sans à-nouveau envoie le même montant en mouvement et en solde : c'est **sa** décision,
écrite dans l'OpenAPI, pas une déduction du serveur. »

### ⑤ Balances antérieures : lecture tolérante, projection **qui n'affirme rien** (D-147-10)

Aucune migration. Une balance à 2 colonnes est restituée en `checksumVersion: v1`, et la projection
**n'invente pas** la grandeur absente. **L'UI doit refléter cette honnêteté** : sur une balance `v1`,
ne pas afficher deux grandeurs distinctes comme si elles l'étaient.

### ⑥ Sage : la grandeur absente est **dérivée et annoncée** (D-147-6)

Le parser déclare ce que le fichier portait (`familleColonnes`) ; le normalizer dérive ce qui manque
et **le dit dans un avertissement**. FE-025 rend déjà les avertissements tels quels — vérifier que
ces nouveaux avertissements sortent bien.

### ⚠️ Réserve sur la vérification 5, et ce qu'elle apprend

Le 403 `EMAIL_NOT_VERIFIED` est bien émis par `:3007` avec son `code` (confronté sur une session
réelle non vérifiée), et le gate le traite comme autoritaire. **Mais l'écran
`atelier.gate.EMAIL_NOT_VERIFIED` n'est pas atteignable dans le parcours nominal** : le *shell* de
l'app arrête l'utilisateur non vérifié **avant** la page du module (« Vérification requise »), si
bien que `useAtelierAccess` n'interroge jamais `:3007`. Cet écran ne sert donc qu'au cas de
**désynchronisation** — jeton portant `emailVerified: false` alors que `/users/me` dit l'inverse.
Ce n'est pas un défaut (c'est de la défense en profondeur), mais c'est une UI dont le seul chemin
d'accès est un désaccord entre deux sources : à savoir avant de l'enrichir.

### Deux défauts de stack trouvés — et pourquoi ils avaient survécu

Le gate a buté sur deux pannes qui **fermaient tout le module dans un navigateur**, tout en laissant
le service répondre `200` à chaque `curl` :

1. **`CORS_ALLOWED_ORIGINS` n'était pas passé à `balance-service`** dans `docker-compose.yml` (les
   six autres services l'ont). L'allowlist vide **désactive** CORS : préflight `404`, aucun en-tête
   `Access-Control-*`. Un appel serveur-à-serveur ne fait pas de préflight — d'où l'angle mort.
2. **Artefacts de référentiel checksum-invalides sur clone Windows** : `.gitattributes` absent ⇒ git
   réécrit les `.json` d'`assets/` en CRLF ⇒ `502 REFERENTIEL_INTEGRITY`, avec un message qui accuse
   l'artefact alors que son contenu est intact.

→ `tickets/TICKET-OPS-atelier-injoignable-depuis-un-navigateur.md` — **les deux sont corrigés
durablement le 2026-08-08**, et l'audit a montré que chaque piège était encore armé ailleurs :

- **CORS** ajouté à `balance-service` **et** à `bilan-service`, dernier service applicatif qui en
  manquait. Les **7** répondent désormais au préflight avec la bonne origine.
- **`.gitattributes`** (`-text` sur les artefacts à checksum) posé dans `balance-service` **et**
  `bilan-service` — dont les **cinq** artefacts étaient **déjà** en CRLF (`i/lf w/crlf`), donc tous
  checksum-invalides : le défaut y était actif, simplement sans témoin faute d'écran de Bilan livré.
  Branches `fix-gitattributes-artefacts-checksum` (`8bcf651`, `ac6d5b5`), non poussées.

⚡ **Piège appris en corrigeant, consigné dans les deux `.gitattributes`** : une fois `-text` posé,
`git add --renormalize` **n'annule pas la corruption, il l'importe** — git enregistre les octets de
l'arbre de travail tels quels, donc les CRLF entrent dans le dépôt et se propagent à tous les postes,
Linux compris. Le geste correct est `rm` puis `git checkout --`, pour repartir des octets de l'index.
