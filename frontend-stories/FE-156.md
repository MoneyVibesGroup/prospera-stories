## User Story

**En tant qu'**associé ou collaborateur,
**je veux** ouvrir une note ou un plan déjà rempli avec les données du client, compléter ce qui manque, le voir, le télécharger en Word
pour le retoucher, puis le redéposer,
**afin de** ne rien ressaisir et de garder la main sur le texte remis à la banque.

## Ce qui est attendu (un parcours facile, même pour un paresseux)

1. **Un seul bouton « Générer »** par document ; le document s'ouvre **déjà rempli** : entreprise, historique, projet, prévisionnel,
   garanties, risques. Seuls les **blocs surlignés** sont à compléter, avec un compteur (« 3 informations à compléter »).
2. **Pour chaque bloc à compléter, deux brouillons proposés** (des modèles remplis avec les données, jamais une IA) ; « Accepter le
   brouillon » le pose, le cabinet peut le modifier. Rien n'est appelé auprès d'une IA.
3. **Le plan d'affaires d'une jeune société** commence par un **questionnaire de huit questions** ; les réponses remplissent les
   hypothèses du prévisionnel, et l'écran montre ce qui en est déduit (CA annuel visé 75 600 000, marge brute 18 900 000, charges fixes
   15 000 000, excédent brut estimé 3 900 000).
4. **« Valider » reste grisé** tant qu'un bloc est à compléter (« Complétez les informations surlignées pour valider »).
5. **Chaque document se voit dans l'application** (aperçu) avant tout téléchargement, puis se **télécharge en Word (modifiable)** ou en
   PDF.
6. **Redéposer la version modifiée** : un vrai bouton de téléversement (et glisser-déposer) ; la version modifiée **remplace** la
   générée, les deux restent dans l'**historique**, avec la date et l'auteur. Régénérer demande confirmation si une version modifiée
   existe.
7. **Les lettres** (demande, affirmation, décision des associés, engagement de domiciliation) se génèrent, se voient, se téléchargent
   pour être **imprimées, signées, puis déposées signées** comme pièces exigées (FE-153).

## Critères d'acceptation

- **AC-1** : maquette ajoutée au prototype cabinet et validée par l'utilisateur le 21/11 (PR #741). **Fait.**
- **AC-2** : la note d'Ets Kossi s'ouvre avec les chiffres de référence de STORY-1109 (HT 26 483 051 + TVA 4 766 949 = 31 250 000 TTC ;
  apport 6 250 000 ; prêt 25 000 000, mensualité 658 346 ; couverture retenue 197 %) et **trois informations à compléter** ; le compteur
  tombe à zéro quand elles sont complétées.
- **AC-3 (voir)** : **tout document généré** (note, plan d'affaires, lettre de demande, lettre d'affirmation, décision des associés,
  engagement de domiciliation) a un « Voir » qui affiche un **aperçu** dans l'application, avant tout téléchargement ; le même « Voir »
  existe pour la version modifiée déposée et pour chaque version de l'historique.
- **AC-4 (upload)** : « Déposer la version modifiée » est un **vrai téléversement** (sélecteur de fichier, glisser-déposer) vers
  `POST …/documents` (cible `DOCUMENT_GENERE`, STORY-1104) ; types DOCX et PDF et taille maximale nommés à l'écran ; progression et
  « Annuler » ; refus par texte d'écran (`FORMAT_NON_ACCEPTE`, `FICHIER_TROP_VOLUMINEUX`, `FICHIER_ILLISIBLE`) ; l'historique montre
  la version générée et la modifiée, avec date et auteur.
- **AC-5** : chaque refus du serveur par son code, avec un texte d'écran : `BLOCS_A_COMPLETER`, `VERSION_MODIFIEE_EXISTE`,
  `PROFIL_NON_CONCERNE`, `BANQUE_REQUISE`, `DONNEES_MANQUANTES` (avec les champs), `RENDU_INDISPONIBLE`, `QUESTIONNAIRE_INCOMPLET`,
  `DOSSIER_FINANCEMENT_NON_MODIFIABLE`.
- **AC-6** : la note n'est proposée qu'à une société établie, le plan d'affaires qu'à une jeune société ; la lettre de demande est
  une par banque.
- **AC-7** : types générés ; e2e simulés ; **gate réel** : générer la note, compléter les trois blocs, la voir, télécharger le Word,
  **déposer un vrai .docx modifié**, relire l'historique.
