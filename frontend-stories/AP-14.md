## User Story

En tant qu'**exploitant de la plateforme Money Vibes**,
je veux **voir ce qui coince dans les encaissements et pouvoir débloquer les quelques cas qui le
demandent**,
afin d'**intervenir sur les incidents sans avoir accès aux opérations métier de mes clients**.

---

## Contexte — pourquoi une console *bornée*

Le PRD a été révisé sur ce point après relecture : `FR-P63` disait *« console d'exploitation »* en
quatre mots, pour ce qui est un écran entier. Il liste maintenant **quatre actions, et pas une de plus** :

1. Suivre les demandes de paiement
2. Consulter les **notifications de fournisseur rejetées**, avec leur motif
3. **Réacheminer** une demande
4. Consulter les **écarts de rapprochement**

> ⚡ **Ce que cette console n'est pas :** un back-office métier. Money Vibes n'encaisse pas pour ses
> clients, ne déclare pas leurs paiements en espèces, n'annule pas leurs encaissements et ne valide
> pas leurs déclarations. Ces actes appartiennent à l'organisation cliente et à ses rôles — le
> backend les refuse (`STORY-156`, `STORY-158`), la console ne doit pas les proposer.

## Périmètre

### 1 · Suivi des demandes

Liste filtrable par organisation, état, période, fournisseur. Colonnes : créance, payeur, montant,
état, fournisseur, âge.

**Détail d'une demande** : sa chronologie — émission, ouvertures du lien, encaissements successifs
avec **leurs frais**, solde restant.

⚠️ **Lecture seule.** Aucune action métier depuis cet écran.

### 2 · Notifications de fournisseur rejetées

Ce que `STORY-154` AC 1 produit : les notifications **non signées ou mal signées**, rejetées et
tracées.

| Affichage | Pourquoi |
|---|---|
| Fournisseur, horodatage, **motif du rejet** | — |
| **Volumétrie dans le temps** | ⚡ Une avalanche de rejets signale soit une attaque, soit une **rotation de clé qu'on a manquée**. Un tableau sans courbe rate le second cas |

### 3 · Réacheminement d'une demande

`FR-P12` / `STORY-152` §E : **explicite, jamais automatique**, et il exige la **révocation prouvée**
de la demande précédente chez le fournisseur d'origine.

L'écran doit rendre cette contrainte **lisible**, pas seulement l'appliquer :

- Le bouton est **inactif** tant que la révocation n'est pas confirmée par le backend
- Le motif de l'inactivité est **affiché** — pas un bouton grisé sans explication
- Un avertissement rappelle **pourquoi** : un lien déjà communiqué au payeur produirait deux chemins
  de paiement vivants, donc un risque de **double encaissement**

### 4 · Écarts de rapprochement

Les quatre natures produites par `STORY-157` :

| Écart | Ce qu'il veut dire |
|---|---|
| Au relevé, absent de Prospera | Un encaissement qu'on n'a pas vu |
| **Dans Prospera, absent du relevé** | ⚡ **Le plus grave** — à faire ressortir visuellement |
| Montants divergents | Frais non anticipés, ou erreur |
| Rapprochement multiple possible | Le rang 3 a trouvé plusieurs candidats |

Filtres par organisation, fournisseur, période, nature. Export.

⚠️ **La console consulte les écarts ; elle ne les arbitre pas.** L'arbitrage appartient à
l'organisation cliente.

### Hors périmètre

Déclarer, valider ou annuler un encaissement · émettre une demande pour un client · attribuer une
grâce *(→ AP-16)* · gérer les abonnements *(→ AP-15)*.

## Critères d'acceptation

- [ ] Les **quatre** panneaux existent — **et aucun cinquième**.
- [ ] Le suivi des demandes est **en lecture seule** : aucune action métier n'est proposée.
- [ ] Le détail d'une demande affiche ses encaissements successifs **avec leurs frais** et le solde
      restant.
- [ ] ⚡ Le solde affiché est **ventilé** certain / sous réserve — jamais un nombre unique
      (`STORY-159` AC 2).
- [ ] Les notifications rejetées affichent leur motif **et une volumétrie dans le temps**.
- [ ] Le bouton de réacheminement est **inactif** sans révocation confirmée, avec **le motif affiché**.
- [ ] Un avertissement explique le risque de double encaissement avant réacheminement.
- [ ] Les quatre natures d'écart sont distinguées ; « dans Prospera, absent du relevé » ressort
      visuellement.
- [ ] Export des écarts (organisation, fournisseur, période, nature).
- [ ] ⚡ Les montants respectent les décimales de leur devise ; **aucun total toutes devises
      confondues** n'est affiché (`FR-P57`).
- [ ] `403` hors rôle géré ; i18n FR ; erreurs `{ message, code }`.
- [ ] Tests : rendu des quatre panneaux, lecture seule, bouton inactif motivé, distinction des écarts.
