- (event) Run créé le 2026-11-10, lot 1 (validation PO ven. 13/11), mode accompagné, exigence élevée. Amont : Connecteurs ≠ Reprise (boîte aux lettres vs déménagement), adaptateurs partagés ; requis en février pour l'Odoo du distributeur.
- (decision) UN PROPRIÉTAIRE PAR DOMAINE (PO, accord explicite) : Rachid le fixe à l'installation, domaine par domaine, dans la console ; le propriétaire a toujours raison, l'autre logiciel ne fait que recevoir.
- (decision) Assureur : la répartition des propriétaires DÉPEND du logiciel, que le PO n'a pas encore vu ⇒ à fixer après l'avoir vu (hors février).
- (decision) IMF : le logiciel de l'IMF a toujours raison sur l'argent (prêts, soldes, épargne) ; Prospera est propriétaire de ce qu'il crée sur le terrain (visites, promesses, comptes-rendus, GPS) ; un remboursement saisi sur le terrain reste « en attente de confirmation » jusqu'à acceptation.
- (assumption) Propositions du document collé, transmises par le PO sans les retirer ⇒ traitées comme acceptées, à confirmer d'un mot : mode d'Odoo selon l'offre (complète / Finance & Recouvrement ⇒ temporaire ; Terrain & Ventes / Stock & Logistique ⇒ permanent, cas le plus fréquent) et construction « comme si permanent » ; trois garde-fous (mouvements pas totaux, jamais d'argent corrigé en silence ⇒ file des écarts, contrôle nocturne) ; trois niveaux de fraîcheur (minutes / heure / avant 6 h) ; comportement en panne (mentions de fraîcheur, file d'envoi, refus avec « Corriger et renvoyer », alerte MV puis admin client après 30 min, jamais de blocage) ; ordre de livraison Odoo pour février.
- (assumption) Versions d'Odoo à supporter non précisées (ex. 17 et 18, Community et Enterprise) ⇒ question ouverte.
- (change) PRD rédigé : UJ-6 (Kodjo), UJ-7 (Awa tranche un écart), UJ-8 (Rachid fixe les propriétaires) ; FR-1 à FR-17 en 6 parties ; NFR-1 à 6 ; SM-1 à 5 + contre-indicateurs ; contrat de module + note de doctrine (autorité métier extérieure) ; questions QK-1 à QK-3.
- (decision) QK-1 (PO) : TOUTES les versions d'Odoo. Faits vérifiés : XML-RPC/JSON-RPC dépréciés depuis Odoo 19, suppression annoncée Odoo 22 (Online 21.1) ; JSON-2 depuis 19 ; API externe d'Odoo Online réservée au plan Custom ; factures account.invoice ≤ 12 puis account.move ≥ 13. ⇒ détection de version, deux API, générations de modèles, prérequis plan Custom, matrice de tests des versions rencontrées.
- (decision) QK-2 (PO) : propositions du récit GARDÉES, « sauf si meilleur ».
- (assumption) Recommandations à valider : (1) file des écarts + écran de santé livrés AVEC l'étape 3 (l'argent circule) ; (2) alerte admin si données de nuit absentes à 6 h ; (3) seuils : orange au délai cible, rouge à 3× (15 min / 3 h), 6 h fixe pour la nuit (au lieu de 2×, contre les fausses alertes de coupures brèves).
- (decision) Validé (PO) : file des écarts + écran de santé livrés AVEC l'étape 3 ; alerte admin si données de nuit absentes à 6 h ; seuils orange au délai cible, rouge à 3× (15 min / 3 h), 6 h fixe pour la nuit ; message d'action dès l'orange. Plus aucune question ouverte sur le PRD Connecteurs.
- (event) 2026-11-11 : controle cible (controle-cible.md, 21 contradictions dont 3 critical) ; reponses du PO en bloc, toutes selon la recommandation.
- (decision) QC-2 (PO 2026-11-11) : Connecteurs est UN module commercial, ajoute d'office des que le contrat declare un logiciel du client, inclus dans la plateforme complete.
- (decision) QC-3 (PO) : la Reprise cree les tables de correspondance ; Connecteurs en prend une copie au demarrage de la synchro et en est ensuite seul proprietaire.
- (decision) QC-4 (PO) : paquet d'adaptateurs commun Reprise/Connecteurs, identifiants propres a chaque module ; la spine place le paquet.
- (decision) QC-5 (PO) : la Reprise charge produits, prix et stock ; Connecteurs prend le relais a partir d'un point de coupure date.
- (decision) QC-7 (PO) : un retour arriere laisse intactes les ecritures faites chez le client : SANS_PERTE cote Prospera ; mouvements inverses PROPOSES, jamais automatiques ; file d'envoi suspendue tant que le DSI n'a pas confirme.
- (decision) QC-8 (PO) : un ecart ouvert bloque l'arret de la synchro d'un domaine d'argent.
- (decision) QC-10 (PO) : prospect = lecture seule du vrai logiciel avec identifiants dedies, ecritures toujours interceptees, pas de bac a sable sans Money Vibes.
- (decision) QC-11 (PO) : sur site, seuls des compteurs remontent a Money Vibes, par le controle quotidien ; l'alerte a l'administrateur du client reste sur l'instance.
- (decision) Amont (PO) : la spine de la coque (AD-7) recoit des champs de fraicheur normalises, une table de seuils orange/rouge dans la coque et une ligne de bandeau 'file d'envoi' ; le module ne rend pas de bandeau.
- (event) 2026-11-11 : PRD corrige apres controle cible (FR-18 essai, FR-19 etats publies, FR-20 relais de la Reprise, FR-21 mise a jour et retour arriere ; C1 -> C13 ; QK-4 -> QK-14 tranchees ; hypotheses A-1 -> A-15 indexees au PRD).
